# Working in this repository

Next.js 16 App Router template. Read this before writing code; `docs/` has the long
form and the reasoning. (`CLAUDE.md` imports this file — edit here, not there. The
block above is generated by `next dev`; leave it alone.)

## Non-negotiables

**Layers point downwards only.** `app → features → components → components/ui`,
`components → api → store`, `app` and `features` may use `server`, everything may use
`i18n`/`schemas`/`utils`/`types`/`config`/`constants`. Enforced by
`import-x/no-restricted-paths`. In particular: **`components/` must not import
`server/`** — data fetching belongs in `app/` or `features/`, which pass props down.

**No barrel files.** Import the file: `~/components/ui/Button/Button`, never
`~/components`.

**`process.env` only in `src/config/env.ts`.** Everywhere else, import `CLIENT_ENV` or
call `getServerEnv()`.

**One HTTP function.** `apiFetch` in `src/api/client.ts`. Endpoints go in
`src/api/api.ts` as `<subject><HttpVerb>`. Do not add axios, a second fetch wrapper, or
a "server version".

**Every write is a Server Action built from `actionClient` / `authAction`** in
`src/server/actions/client.ts`. Never export a bare `'use server'` function that
touches user data — a `'use server'` export is a public HTTP endpoint.

**`type`, not `interface`** (except declaration merging). Infer types from zod schemas.

**English everywhere** except `src/i18n/messages/*.json`.

## Reading data

Default: a Server Component awaits the DAL (`src/server/dal/*`) and passes objects as
props. No client cache.

Client-owned reads only (infinite lists, live search): TanStack Query, seeded with
`prefetchInfiniteQuery` → `dehydrate` → `HydrationBoundary`. Use
`prefetchInfiniteQuery` for infinite queries, and **`await` it** before `dehydrate` — it
never throws, so a missing `await` silently ships an empty cache.

Never `initialData` — it is treated as fresh and never overwrites existing cache data.

Never fetch the same dataset both server-side and via `useQuery`.

Caching is explicit: `next: { revalidate, tags }` on every cacheable read. A bare
`fetch` is uncached at runtime in Next 15+. A request with a `cookie` or `authorization`
header is never Data-Cached — which is why per-user reads are automatically uncached.

## Writing data

| Situation                                                       | Use                                    |
| --------------------------------------------------------------- | -------------------------------------- |
| Mutation invalidates the TanStack cache                         | `useMutation(mutationOptions(action))` |
| Server-owned data, optimistic                                   | `useOptimisticAction`                  |
| Server-owned data, plain                                        | `useAction`                            |
| Form                                                            | `useHookFormAction`                    |
| Multi-step (OTP, passkey), webhook, native client, >1 MB upload | Route Handler                          |

A Server Action's response already carries a re-rendered RSC payload when it calls
`updateTag`, `revalidatePath`, `refresh`, writes a cookie, or redirects. Do not add
`router.refresh()`.

Invalidation:

- `updateTag(tag)` — immediate + re-render. Server Actions only. The default.
- `revalidateTag(tag, 'max')` — stale-while-revalidate, no re-render. Webhooks.
- `refresh()` — re-renders dynamic (uncached) data only. Server Actions only.
- `revalidateTag(tag)` with no second argument is deprecated in Next 16.

Tags live in `src/server/cache/tags.ts`. Never inline a tag string.

## Authorization

In the DAL, next to the read (`requireSession()` inside `getProfile()`), and in
`authAction` for writes. **Not** in `proxy.ts` (CVE-2025-29927) and **not** in a layout
(Partial Rendering means layouts do not re-run on navigation).

Route Handlers get no CSRF protection from the framework. Check `Origin` by hand — see
`app/api/auth/refresh/route.ts`.

## Errors

Client: `reportError(error)` → toast + Sentry. For next-safe-action hooks,
`reportActionError(error)` → toast only (the server already reported it).

Server: `handleServerError` maps to a translation **key**, never a message. Stack traces
stay server-side.

Success toasts stay at the call site. Error toasts are declarative (`meta.errorToast`).

## UI

Wrap Base UI; do not reimplement a primitive that exists. Style state with its `data-*`
attributes (`[data-disabled]`, `[data-popup-open]`, `[data-starting-style]`), never a
JS-computed class.

`components/ui` takes **already-translated strings** — no `t()`, no stores, no API.

CSS Modules named `<ComponentName>Styles.module.css`. No hex values (use tokens from
`src/styles/tokens.css`). **Logical properties only** — `margin-inline`,
`inset-inline-end`, `text-align: start` — never `left`/`right`, because `ar` is RTL.

No `'use client'` on a component without hooks.

Queries in tests use role + accessible name. Never `data-testid`.

## Forms

One zod schema, validated by react-hook-form (`standardSchemaResolver`) _and_ by the
action (`.inputSchema()`). Validation messages are i18n **keys**, translated at display.
Prefer `register` (uncontrolled); use `ControlledTextField` only when a value must drive
something else as you type.

## Files that go together

Adding `src/components/ui/Foo/Foo.tsx` means also adding:

- `src/components/ui/Foo/FooStyles.module.css`
- `__tests__/components/ui/Foo/Foo.test.tsx`
- `stories/components/ui/Foo/Foo.stories.tsx`

`__tests__/` and `stories/` mirror `src/` 1:1. E2E lives in `e2e/` and is flat.

## Things that will waste your time if you do not know them

- **Every route is dynamic** because the root layout reads cookies. Adding
  `generateStaticParams` anywhere gives `DYNAMIC_SERVER_USAGE` — a 500 with no message
  in production. See `docs/caching.md`.
- **`notFound()` UI is not server-rendered** (upstream
  [#62228](https://github.com/vercel/next.js/issues/62228)). The status is correct; the
  body arrives after hydration. Not a bug you introduced.
- **`next/experimental/testmode` imports need the `.js` extension** and only export
  `defineConfig` / `test`; get `devices`, `expect` from `@playwright/test` and `http`,
  `HttpResponse` from `msw`.
- **`test.use({ mswHandlers })` is broken** with Playwright 1.62. Use
  `test.beforeEach(({ msw }) => msw.use(...handlers))`.
- **Playwright must use `localhost`, not `127.0.0.1`** or Next's dev server 403s every
  chunk and nothing hydrates.
- **pnpm 11 ignores the `pnpm` field in `package.json`** — `allowBuilds` lives in
  `pnpm-workspace.yaml`.
- **TypeScript is pinned to 6.0.3 and ESLint to 9.x** by peer caps in `typescript-eslint`
  and `eslint-plugin-react`. Do not bump them casually.
- **`next lint` no longer exists.** `pnpm lint` runs `eslint .`.
